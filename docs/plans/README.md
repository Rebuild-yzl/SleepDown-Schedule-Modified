# 设计修改计划

这里存放**本个人的修改版**（SleepDawnModified）对应用做的界面、交互与体验改造计划。上游主线不维护这些文档，它们是改动前的设计与取舍记录，用来回答"为什么改成这样"，避免下次又从头讨论一遍。

## 适合放在这里

- 界面重做、布局调整、配色/字体/动效方案，以及同一个问题的备选方案比较。
- 交互流程改动（入口位置、确认步骤、弹层形态）及其对已有功能的影响。
- 与上游不同的产品取舍：改了哪些、刻意不改哪些、后续升级上游时如何合并。

不适合：根因调查与验收记录（放 [../reports/](../reports/)，或 [../](../) 根目录的日期报告）、发布说明（放 [../../release-notes/](../../release-notes/)）、长期模块规范（放 [../architecture/](../architecture/) 等专项文档）。

## 命名与结构

- 一个计划一个文件：`YYYY-MM-DD-简短主题.md`，例如 `2026-11-02-settings-page-restructure.md`。
- 状态写在文件开头：`草案` / `已确认` / `实施中` / `已完成` / `已放弃`；实施完成后补一段结论和实际落地情况，不要重写原计划。
- 从 [TEMPLATE.md](TEMPLATE.md) 复制起步。计划要以真实代码和截图证据为依据，写清涉及的页面与关键文件。
- 计划与实现冲突时以代码为准，回头更新计划里的结论。

## 与长期规则的关系

计划是某个改动的设计依据，不覆盖 [AGENTS.md](../../AGENTS.md) 中的长期约定（数据安全、兼容性、设计系统复用、验证入口）。动手前按 AGENTS.md 选择最小充分验证；涉及公共控件时先读 [设计系统](../architecture/SLEEPDOWN_DESIGN_SYSTEM.md)。

## 参考图与 HTML 参考稿

- 用户提供的原始参考图（例如 `代办ui.jpg`、`事件倒计时ui.jpg`）是**本地素材**，已在根 [.gitignore](../../.gitignore) 中排除，不进入版本库。
- 参考图里的版式与交互被转写为 [design-reference-todo-countdown.html](design-reference-todo-countdown.html)：自带样式、无外部资源、不引用未入库图片，可直接用浏览器打开或打印为 PDF。
- 实现与验收以 HTML 参考稿和计划正文为准；参考图只用于回看原始意图。调整版式或令牌时先改参考稿，再改代码。
