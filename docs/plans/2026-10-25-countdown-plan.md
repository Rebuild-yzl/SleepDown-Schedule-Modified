# 事件倒计时改造计划

- 状态：草案（待确认）
- 日期：2026-10-25
- 参考稿：[待办与倒数日设计参考](design-reference-todo-countdown.html)（原始参考图由用户在本地放入本目录，未纳入版本库）
- 涉及：新增 `feature/plan` 倒数日页、`data/local`、`data/repository`、Room 迁移
- 配套计划：[待办（四象限）改造计划](2026-10-25-todo-quadrant-plan.md)；页面宿主、Dock 第三项与分段控件见该计划第 3 节，此处不重复

## 1. 目标

在「计划」页的「倒数日」分段中管理事件倒计时：大号实时剩余时间（天时分秒）+ 事件卡片列表，支持每年重复（生日、纪念日）、置顶、编辑与删除。

明确不做：日历订阅、共享倒数日、农历节日自动生成、桌面组件（P3）。

## 2. 现状与证据

- 仓内没有任何倒计时/生日相关表、页面或通知（`rg -i "countdown|birthday"` 仅命中 App 标识与文案，无业务实现）。
- 通知能力集中在 `feature/reminder/NotificationScheduler.kt`，课程提醒、勿扰与实时更新已各自占用通道，新增提醒必须复用通道管理，不新开一套 Alarm/前台服务。
- 全局时间基准来自 `ScheduleConfigEntity.termStartDate` 与系统时区；倒计时事件与课表周次无关，属于独立域。

## 3. 时间语义（本功能的核心）

**事件保存的是本地墙上时间**，不是绝对时间戳：

```kotlin
val targetDate: String   // ISO yyyy-MM-dd，必填
val targetTime: String?  // HH:mm，null = 全天事件
val repeatYearly: Boolean
```

理由：考试 09:00、生日当天、纪念日都按"本地日历上的那一刻"理解；存 epoch 会在跨时区、夏令时或换设备时漂移。渲染时才用 `ZoneId.systemDefault()` 合成 `ZonedDateTime`。

派生规则（全部进单测，固定 `Clock` + 固定时区）：

| 概念 | 规则 |
| --- | --- |
| 目标时刻 | `LocalDate.parse(targetDate).atTime(targetTime ?: "00:00")` 于当前时区；每天 00:00 视为"当天开始" |
| 每年重复 | 用当前或下一年的同月同日重建；2 月 29 日在平年回落到 2 月 28 日，并在表单中明示 |
| 卡片「还有 N 天」 | `ChronoUnit.DAYS.between(今天, 目标日期)`，按**日历日**而非 24 小时倍数；0 → 「今天」；负数 → 「已过 N 天」 |
| Hero 实时剩余 | `Duration.between(now, 目标时刻)`，向上取整到秒；> 0 才显示"还有"，否则显示「已过 …」 |
| 排序 | 置顶优先 → 未过期按目标时刻升序 → 已过期按最近过期在前，统一排在最后 |
| 跨天刷新 | 日期变化（零点、手动改时间、时区变化）触发整页重算；秒级刷新只作用于 Hero |

说明：卡片故意用日历日，避免每秒重算列表；这也解释了参考图中"37 天"与"36天5时39分55秒"同时出现。

## 4. 页面

### 4.1 版式

```text
页头：倒数日                        [排序]
        四级笔试准考证打印
     36天5时39分55秒              ← Hero，34sp 等宽数字，单位 17sp
┌────────────────────────────┐
│ 四级笔试准考证打印      还有 37 天│
│ 2026年12月01日               │
└────────────────────────────┘
┌────────────────────────────┐
│ 四六级口试              还有 48 天│
│ 2026年12月12日               │
└────────────────────────────┘
 [视图][课程表][待办][倒数日·选中][设置] (+)
```

- Hero 承载"最近一个未过期事件"：名称 18sp + 计时 34sp（`FontFeatureSettings` 等宽数字，避免跳动），单位字 17sp；没有未来事件时整块换成空态文案，不用过期事件顶替。
- Hero 不加卡片：大数字直接压页面底色，壁纸场景用文字软阴影（与首页 `HomeReadableText` 同族规则），避免玻璃表面削掉数字重量。
- 页面不设返回按钮，与待办页一致：系统返回回「课程」，导航规则见待办计划第 3 节。
- 列表卡片：72dp 高，左侧标题 16sp + 日期 12sp 次级，右侧「还有 / 已过」12sp + 数字 22sp 强调色（过去与未来用不同色阶，不只改字重）。
- 日期格式统一「yyyy年M月d日」，与参考图一致；当天不加"今天"标记，避免与右侧天数重复表达。
- 「排序」按目标日期 / 创建时间 / 置顶切换，默认按目标日期；「导入生日」在 P2 前不出现（不摆未实现按钮）。

### 4.2 新建与编辑

- 加号与待办页同一个：Dock 右侧、56dp 主色圆按钮。
- 表单（`CenterLiquidDialog`）：标题（必填 ≤ 40 字）、日期（`SleepDownPickerDialog` 日期选择，默认今天）、时间（开关，默认全天；开启后为时间 Picker）、每年重复（开关）、备注（≤ 300 字）、置顶（开关）。
- 保存前校验：日期不早于今天时给"已过期"提示但不阻止（补记过去的纪念日是合理需求）。
- 删除在长按菜单里，与待办一致；删除不弹二次确认，用 3 秒撤销条兜底。

### 4.3 秒级刷新与性能

- 计时器只在 Hero 内部订阅：`produceState` + `delay(1000 - now % 1000)` 对齐整秒，页面其余部分不参与重组。
- 页面进入后台（`LifecycleResumeEffect` 离开 ON_RESUME）停止计时，回到前台重新对齐，不长期持有 Timer/Wakelock。
- 列表中"还有 N 天"只在日期变化或页面恢复时重算，不在秒级刷新里遍历。
- 动画：秒数字变化不做缩放/高亮，避免每秒钟干扰阅读；切换排序与增删使用既有列表动画。

## 5. 数据与迁移

```kotlin
@Entity(tableName = "countdown_events")
data class CountdownEventEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val note: String = "",
    val targetDate: String,        // ISO yyyy-MM-dd
    val targetTime: String?,       // HH:mm，null = 全天
    val repeatYearly: Boolean = false,
    val pinned: Boolean = false,
    val createdAt: Long,
    val updatedAt: Long
)
```

- 与待办同一次迁移：`APP_DATABASE_VERSION` 47 → 48，`MIGRATION_47_48` 内建两张表（待办 + 倒数日），避免同一发布里两次升版。
- 索引：`(targetDate)`、`(pinned)`。
- 备份：与待办一致，`.sleepdown` v1 本轮不包含倒计时数据，导出/恢复行为不变；跨设备迁移留到 P3 单独评审 codec 扩展。

## 6. 影响范围

- 与待办共用 Dock 与加号，导航回归项（5 项索引映射、尺寸收紧、选中态、返回行为、今日项隐藏）见待办计划第 3 节，不重复。
- 不触碰课程、节次、备份、导入、AI 助理任何现有链路。
- 时区与夏令时：只依赖 `java.time`，不手写天数/毫秒换算；换时区后在下次恢复或零点重算。

## 8. 分阶段

- **P0**：表 + DAO + 仓储 + 列表与 Hero（只读）。
- **P1**：新建/编辑/删除/撤销、置顶、排序、每年重复。
- **P2**：提醒（目标日前 1 天 20:00 与当天 09:00，复用通知通道）、导入生日（`READ_CONTACTS`，权限拒绝时保留手动添加，去重按姓名+月日）。
- **P3**：桌面组件、`.sleepdown` 扩展、农历节日模板。
