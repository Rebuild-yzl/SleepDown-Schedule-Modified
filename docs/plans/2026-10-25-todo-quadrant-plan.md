# 待办（四象限）改造计划

- 状态：草案（待确认）
- 日期：2026-10-25
- 参考稿：[待办与倒数日设计参考](design-reference-todo-countdown.html)（原始参考图由用户在本地放入本目录，未纳入版本库）
- 涉及：新增 `feature/plan`、`data/local`、`data/repository`、Dock 导航、Room 迁移
- 配套计划：[事件倒计时改造计划](2026-10-25-countdown-plan.md)（共用同一页面宿主与导航）

## 1. 目标

给 SleepDawnModified 增加"待办"，按**重要 × 紧急**四象限组织，支持截止日期、完成与逾期提示，入口是首页 Dock 新增的第三项「待办」，与倒数日并列。

必须先说清不做什么，避免范围失控：

- 不做标签、子任务、重复规则、协作；分类（参考图的「全部分类」）与提醒推迟到 P2。
- 不改动课程数据、时间规则与已发布的导入/备份协议。
- 待办是**应用级**数据，不跟随课表切换（与课程、节次不同域）。

## 3. 导航（两个新功能共用）

按应用现在的结构，Dock 就是一级导航，设置首页本身也是 Dock 里的一页；因此待办与倒数日直接作为**独立的一级页**插入 Dock，不做「计划」汇总页，也不做页内分段控件。

1. Dock 统一为 5 项，普通与并列模式相同：**视图 / 课程表 / 待办 / 倒数日 / 设置**。不再按模式增删。
2. 「视图」= 原「今日」日视图，只改 Dock 名称，页面实现不变。原「今日」Dock 项**隐藏保留**：在 Dock 列表里过滤掉，`HomeMode.Day`、配置与跳转代码都不删除，去掉过滤即可恢复。
3. 为容纳 5 项收紧尺寸：Dock 高 46dp（原 54dp）、单项宽 50dp（原 56dp）、图标 18dp（原 23–24dp）、文字 9.5sp、加号 52dp（原 56dp），间距 8dp。按 360dp 窄屏核算 `5×50 + 8 + 52 = 310dp`，加左右 16dp 边距仍余 18dp。
4. 页面在 `MainActivity` 内切换：`Screen` 增加 `Todo`、`Countdown`，**不新建 Activity、不加返回按钮、不做跨页转场**。
5. 选中态立即跟随；系统返回从待办/倒数日回「视图」，与设置首页返回行为一致（`BackHandler`）。
6. 加号与首页加号同位置：Dock 右侧、间距 8dp，点开新建表单。
7. Dock 索引是本次最高回归风险：`HomeDockChrome`、`NativeHomeDockChrome`、`ParallelHomeDock`、`HomeNavigationControls` 与 `ScheduleAppUi` 的 `currentDockSelect` 都按索引判断页面；需要改成一份有序列表 + 常量映射，把「最后一栏 = 设置」写死，并确认 5 项在窄屏不溢出、不横向滚动。
8. 平板侧栏同步加入待办、倒数日两项，保证侧栏模式可达。

## 4. 待办页

### 4.1 版式

```text
页头：待办                          [已完成] [排序]
10月25日 周日 · 共 8 项待办           ← 日期行，周条筛选时同步
[一][二][三][四][五][六][日]          ← 周条，点上带未完成计数
┌──────────┬──────────┐
│ 重要且紧急 │ 重要不紧急 │            ← 2×2 均分可用高度，格内各自滚动
│  □ 交作业  │  □ 复习线代 │
│  □ 复习线代 │            │
│  ✓ 整理错题 │            │ ← 放不下的往下滑，不放「还有 N 项」
├──────────┼──────────┤
│ 紧急不重要 │ 不重要不紧急 │
└──────────┴──────────┘
 [视图][课程表][待办·选中][倒数日][设置] (+)  ← Dock 5 项 + 加号
```

- 象限顺序固定：重要且紧急 → 重要不紧急 → 紧急不重要 → 不重要不紧急；颜色只用在标题下的 24×3dp 短线（红 / 黄 / 绿 / 蓝）与计数徽标底色（14% 透明度），不给整卡铺色。
- 卡片：20dp 圆角、12dp 内边距；高不定死，2×2 每行 `weight(1f)` 均分剩余空间，两行等高、两列等宽，条目再多也不撑大卡片。材质走 `glass/` 既有入口，无 Backdrop 时同几何实色降级（参考稿用实色只是低保真示意）。
- 自适应：内容宽 ≥ 360dp 用 2 列，四格均分高度；更窄或字体放大到 1.3 倍时退回单列，单列下卡片按内容撑高（最小 168dp）依次堆叠、改由整页纵向滚动，避免四格被压成一两百 dp 高。
- 每格是一个独立的垂直列表：条目超出一屏就在格内上下滑，**象限高度不变、容量不设上限**，不放「还有 N 项」入口，也不做象限子页面（原来那层子状态整段取消，系统返回因此只在待办 ↔ 视图之间走）。列表滚到边界后把多余的滑动让给外层，不制造嵌套抢手势。
- 滚动提示：内容没放全时，卡片上下边缘做 24dp 渐隐（竖直渐变遮罩，不吃点击、不常驻滚动条）；能完整放下时不显示渐隐。
- 周条：公历 7 天 + 当天 2dp 描边 + 未完成计数点；点某天即按截止日筛选，再点取消，顶部日期行同步。**不采用参考图的农历**：仓内无农历数据源，为它引入第三方表或算法不值得；这一条写在此处备查。

### 4.2 待办行

- 左侧 22dp 圆形勾选（描边 1.5dp，点击区 ≥ 48dp），中间标题 15sp（2 行截断），下方 12sp 元信息。
- 元信息优先级：已逾期（红 `#FF453A`，「已逾期 3 天」）> 今天到期 > 日期（「10月30日 · 还有 5 天」）> 无截止（不显示）。
- 完成态：勾选圈填充并打勾，标题与元信息一起转灰，标题保留下划线（`line-through`，线色与灰字同色）；**行留在原象限，不移除**，逾期红字同时转灰，元信息换成「已完成 · 昨天」这类完成时间。完成时不立即重排，避免刚勾完的行自己滑走；下次进入页面才按排序沉到象限末尾。
- 点击行 = 编辑；长按 = 快捷菜单（编辑 / 移动象限 / 删除，删除用危险色）。
- 勾选：200ms 勾选路径动画 → 勾出现在圈内 → 标题与划线转灰，整行原地不动；再点一次勾选即取消完成。完成**不弹撤销条**——行没有被删掉，没有需要挽回的东西。象限计数、周条计数、页头「共 N 项待办」都只算未完成。
- 删除：立即移除，底部浮出撤销条 3 秒（`LiquidAlertOverlay` 同族表面，不新造 Snackbar 材质），与倒数日一致。

### 4.3 新建与编辑

- FAB 为 56dp 液态蓝按钮，位置右下、上移 16dp 安全区；点开 `CenterLiquidDialog` 表单：标题（必填，≤ 80 字）、象限四选一、截止日期（可选，`SleepDownPickerDialog`，含「今天 / 明天 / 本周日 / 自定义」快捷）、备注（可选，≤ 500 字）。
- 显式「保存」；标题为空时保存按钮置灰并提示。编辑态 FAB 隐藏由表单遮罩接管，不再叠加第二个 FAB。

### 4.4 已完成

- 顶栏右侧「已完成」入口，进入按完成时间倒序的列表，支持单条恢复与「清空已完成」（二次确认，危险色）。
- 完成记录保留 `doneAt`，不物理删除，除非用户清空。
- 象限里保留完成的条目（灰字划线），这个页面是集中查看、恢复与清空的地方，不靠「把完成项从象限搬到这里」来腾位置。

## 5. 数据与迁移

```kotlin
@Entity(tableName = "todo_items")
data class TodoItemEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val note: String = "",
    val quadrant: String,          // IMPORTANT_URGENT | IMPORTANT_NOT_URGENT | URGENT_NOT_IMPORTANT | NEITHER
    val dueDate: String?,          // ISO yyyy-MM-dd，null = 无截止
    val doneAt: Long?,             // null = 未完成
    val createdAt: Long,
    val updatedAt: Long
)
```

- 索引：`(doneAt)`、`(quadrant, doneAt, dueDate)`。
- 象限用 TEXT 存枚举名（与 `notificationMode` 等既有列一致），读取时 `valueOf` 失败回退到 `IMPORTANT_URGENT`，不因单条脏数据崩溃整页。
- 迁移：`APP_DATABASE_VERSION` 47 → 48，新增 `MIGRATION_47_48`（两条 `CREATE TABLE IF NOT EXISTS` + 索引，无 ALTER），并追加 `AppDatabaseMigrationTest` 的 47→48 用例；既有 44→当前 的链路测试必须继续通过。
- 排序规则（固定，进单测）：未完成且逾期 → 未完成有日期 → 未完成无日期 → 已完成（重进页面时沉到象限末尾，不隐藏）；同日按 `createdAt`。

## 6. 影响范围

- **Dock 与首页**：索引映射（普通 4 项 / 并列 5 项）、选中态与加号位置；回归首页切页、加号菜单、三点菜单；按最窄 360dp 确认 Dock 不溢出、不横向滚动。
- **设置页与侧栏**：设置首页保持原样；平板侧栏新增待办、倒数日两项。
- **备份**：`.sleepdown` v1 本轮**不包含**待办数据，避免改动已冻结的 codec 与校验规则；待办仅存在本地，导出/恢复行为与现在完全一致。扩展备份留到 P3 并单独评审。
- **桌面组件**、通知、AI 助理本轮不接入。

## 8. 分阶段

- **P0**：表 + DAO + 仓储 + 页面只读渲染（无编辑）；Dock 入口与分段控件。
- **P1**：新建/编辑/完成/撤销/删除/已完成列表。
- **P2**：分类与筛选（`todo_categories` + 参考图的「全部分类」）、到期提醒（复用 `NotificationScheduler` 的通道，不自建第二套通知）。
- **P3**：备份段、桌面组件、空态插画。
